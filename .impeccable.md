## Design Context

### Users
Ordinary Chinese readers who want to read foreign-language web pages in Simplified Chinese. They don't think in terms of providers, models or reasoning effort; they set the extension up once, then forget it. Most of their time is spent on someone else's web page, where the extension's own UI (the launcher and the translations) must sit quietly beside content it doesn't own. The settings page is visited rarely: to connect an account or key, and occasionally to change a model. The debug log exists for troubleshooting and is the one place where technical detail is expected.

### Brand Personality
Quiet, dependable, out of the way (安静、可靠、退后). Like a system settings pane: nothing competes for attention, every control says plainly what it does, and the user leaves confident it's done. Emotional goal: calm confidence, never "configure me".

### Aesthetic Direction
- Restrained, system-settings feel (macOS System Settings, Linear's settings). Not a marketing page, not a developer console.
- Theme follows the system: both light and dark, via `prefers-color-scheme`.
- Brand hue: the existing indigo (`#535bf2`, roughly `oklch(0.56 0.22 274)`). Neutrals tinted faintly toward it. Accent used rarely: the active nav item, the primary action, focus rings.
- Type: the platform CJK system stack (PingFang SC / Microsoft YaHei / Noto Sans CJK SC) on purpose. It's what system settings use, and shipping a CJK web font costs megabytes. Hierarchy comes from size and weight, not a display face. Monospace only where the content is literally code (model IDs, URLs, durations).
- On third-party pages: the launcher and translations must inherit or blend with the host page's typography and never look like an ad or overlay.
- Anti-references: cards in cards, glowing accents, gradients, colored side-stripe borders, every button primary, explanatory paragraphs that restate the heading.

### Design Principles
1. **Say less.** Each section has one job; help text appears only where a reader would otherwise get stuck. Jargon (provider, model ID, reasoning effort) is either explained in a few plain words or moved behind progressive disclosure.
2. **Grouped like a system pane.** Settings are rows in a few grouped lists with a label on the left and a control on the right, not stacks of form fields inside cards.
3. **Status is visible, not announced.** Connected / not connected, saved / unsaved show as quiet state on the row itself rather than as sentences below a button.
4. **Guest on someone else's page.** Page-side UI stays small, follows the host's colors and fonts where it can, and never covers content.
5. **Both themes are first-class.** Every token has a light and a dark value; nothing is designed in one theme and inverted afterwards.
